### Known gaps / deliberate differences
- No mail transport: default LogMailer logs subject + recipient count only and delivers nothing (Play dev default also delivers nothing). Subjects match DefaultMails exactly; bodies are plain-text renditions carrying the same links. Mailchimp, analytics events, Slack suspicious-name notifications (logged only) and insertLocalDataStoreIfEnabled are not ported. createOrganizationDirectory datastore RPC is best-effort after commit (like Play).
- Errors use the single-message envelope (no Play `chain` entries). Form-binding errors return `Invalid form: <field>: <error key>` instead of Play's `bogusForm.toString` (which echoes submitted passwords).
- Stricter: /auth/resetPassword accepts only ResetPassword tokens (Play accepts any valid token type); expired invites are ignored (Play relies on a cleanup job); emails/organization ids of deleted rows count as taken; every multi-step mutation is one transaction (Play persists partially, e.g. admin-notifier recipient failure after user creation — Rust skips that mail instead); passwords > 72 bytes rejected with 400 (Java strict hasher throws); cookies of deactivated users / deleted orgs are rejected; login only picks identities in live organizations.
- Cookie idle timeout is not configurable (Play conf has none); cookies carrying idleTimeout are honoured on read but never touched/renewed. No CSRF (Play's CSRF filter is disabled too).
- Process note: a bare `cargo fmt` was run once (~08:35) over the whole crate; formatting-only effect on other files possible.
