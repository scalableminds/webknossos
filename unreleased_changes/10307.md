### Added
- Added support for mesh files of format version 10, which store the meshes in merge-tree order and find segments with a static B-tree instead of a hash table. The meshes of an agglomerate are found as a few runs in this order, whatever the name of its mapping, so loading the precomputed meshes of an agglomerate needs only a few requests, especially from remote storage. This includes agglomerates of editable mappings while proofreading.

### Changed
- The mesh chunk data of a request to a Zarr mesh file is read in parallel instead of one range after another.
