## Blocking conclusion and bounded recommendation

**Existing Rust helpers do not implement Scala AnnotationInformationProvider. Do not claim parity for these four typed routes by calling `annotation_access::find(id)` for every `typ`.** `annotation_access.rs` implements saved annotation DAO grants and default runtime restrictions; `annotation_lists::full_json` implements saved, database-backed public serialization. There is no Rust compound resolver, annotation/data-source temporary store, or annotation merge RPC contract. Generic `service_clients.rs` transport alone is insufficient.

A small, honest next batch is a saved-provider foundation (type parser, saved-type alias resolution, route-specific error adaptation, and separated DAO/runtime write checks), with focused tests and an explicit checkpoint that compound support and these four complete route claims remain pending. If implementing only saved variants now, document the limitation and do not mark the complete route implemented in the migration inventory. Full parity needs the real compound provider prerequisites below, in a separately bounded batch; no fabricated annotation, empty merge result, `find(parentId)` fallback, or treating compound types as invalid.

## Provider, type, and cache contract

Sources: `AnnotationIdentifier.scala`, `AnnotationType.scala`, `AnnotationInformationProvider.scala`, `AnnotationStore.scala`, `handler/*.scala`, `AnnotationMerger.scala`.

- Type parsing is exact and case-sensitive: `Task`, `View`, `Explorational`, `TracingBase`, `Orphan`, `CompoundTask`, `CompoundProject`, `CompoundTaskType`. Invalid type error is `Invalid AnnotationType: <typ>`.
- The five noncompound types all select `SavedTracingInformationHandler`. It loads the live annotation by ID using AnnotationDAO read access and **does not require requested type == stored type**. Consequently a valid `View`, `Task`, or `Orphan` path can resolve an actual Explorational row, including for lock. Actual resolved type determines the lock eligibility.
- Saved annotations are never provider-cached. Restrictions are separately loaded via the saved handler and default restrictions. DAO reads allow Public universally, Internal to users in the owner's organization, and Private to owner or administrator of the owner's organization. Neither dataset access nor team-manager status independently grants Private DAO read access.
- Compound types interpret the path ID as a task/project/task-type ID, not an annotation ID. Cache keys are `<type>__<id>`, with a 60-minute expiry. Cache hits return the previously merged annotation without rerunning the handler or updating owner to the current requester. The first requester becomes synthetic annotation owner. Restriction lookup remains separate from this cache.
- CompoundTask: read task, read accessible noncancelled Task annotations for task, select Finished, require nonempty and same dataset, require authenticated requester, read project, register usable dataset data source under task ID, collect task bounding boxes, merge in tracing store.
- CompoundProject: read project, require requester to be project-team manager/admin, collect all live Finished Task annotations in project (this DAO deliberately omits annotation read predicate after separate project authorization), require nonempty and one dataset, register source, collect boxes, merge.
- CompoundTaskType: read task type, read accessible tasks for type, collect accessible noncancelled Task annotations, select Finished, require nonempty and one dataset, register source, collect boxes, merge. Its provide handler does not add a team-manager assertion; its separate restriction handler does.
- Merge calls real `/tracings/annotation/mergedFromIds` with RPC token, `toTemporaryStore=true`, `newAnnotationId=<parent id>`, `requestingUserId`, `remapSegmentIds=true`, annotation IDs, owner IDs, and bounding boxes. Response is AnnotationProto; layers come from it. Synthetic Annotation has parent ID, dataset, no task, first requesting user as owner, actual Compound type, Internal visibility, Active state, OwnerOnly collaboration, unlocked state, empty metadata, and fresh timestamps. It is not inserted into annotations.
- Compound restriction classes override only allowAccess (parent-team manager/admin). Base allowUpdate/allowFinish are false, allowDownload follows access. Thus edit resolves/possibly merges compound first, then rejects with 403. Lock resolves compound first, then owner/type checks; owner may pass on cold cache, but resolved compound type fails. Sharing GET on a cold cache can pass owner and returns actual readable shared rows for synthetic ID (normally none); sharing PATCH can pass initial owner/visibility checks, then fails DAO update access if no live persisted annotation exists. Cache ownership changes these owner checks. Skipping provider work can therefore change authorization, response, and remote/cache side effects even for routes ultimately rejected.

Real provider prerequisites: parent task/project/task-type DAO access, live annotation collection and bounding-box contracts, usable data-source registration, real tracing-store merge JSON/protobuf codec, cache expiry/key/owner semantics, and explicit separate compound restrictions. These are absent from the current shared Rust helpers.

## PATCH /annotations/:typ/:id/edit

Source: `AnnotationController.scala:329`; DAO `Annotation.scala:791-808,847-854,863-876`; defaults in `AnnotationRestrictions.scala`.

Secured action; body is an object with optional `name: string`, `visibility: Private|Internal|Public`, `tags: string[]`, `viewConfiguration: object`. Missing/null optional fields are no-ops; `{}` is valid. Unknown fields (including description) are ignored. Name may be empty; no controller length/character restriction. Tags are written as supplied Seq (duplicates can persist), while loaded annotation tags become a Set.

Order: resolve provider (failure explicitly mapped 404); get provider restrictions (failure 404, `Could not determine annotation access restrictions.`); require `allowUpdate` (403, `You do not have permission to edit this annotation.`). This ignores mutex ownership. Finished or owner-locked saved annotations fail. OwnerOnly allows owner; Exclusive/Concurrent additionally allow same-owner-organization readers under runtime restrictions. Cancelled/Initializing are not Finished and may pass. Admin or task-manager DAO write access does not itself grant runtime update for OwnerOnly.

If visibility is Private, first replace shared teams with empty list; then update name, visibility, tags, and finally requester-specific viewConfiguration, only for present fields. Clearing teams/name/visibility/tags independently require AnnotationDAO update access: owner, owner-organization admin, or task project-team manager. **Ordinary collaborators may pass runtime update yet fail these DAO writes. A viewConfiguration-only or empty request succeeds without DAO update grant.** Existing `lock_for_mutation` prefilters by MUTATE_PREDICATE, so it must not gate every edit request indiscriminately. Need readable locked metadata plus runtime gate, with DAO gate only when DAO-protected fields/Private clearing are present. SQL values remain bound and requester view config uses UPSERT on (_annotation,_user).

No description, modified timestamp, tracing time, contributors, analytics, user activity, tracing-store update, or cache invalidation is performed. Scala operations are sequential, with sharing replacement individually transactional; Rust AGENTS requires multi-step changes transactional, so keep the entire chosen mutation atomic. Success 200 exactly `{"messages":[{"success":"Successfully updated the annotation."}]}`. Update failures use `Could not update the annotation.` except Private team's clear has its own DAO failure; view-config DAO supplies `Could not update the view configuration for this annotation.` in the chain. Runtime failures are 403, DAO assertion/update failures default to 400 (not uniformly 403).

## PATCH /annotations/:typ/:id/editLockedState

Source: `AnnotationController.scala:227`; DAO `Annotation.scala:775`.

Secured action; required query `isLockedByOwner: Boolean`, not JSON DTO. Resolve provider, require actual owner, then actual resolved type Explorational. Neither runtime allowUpdate nor mutex/state gates apply: owners may lock/unlock finished or already locked explorationals. DAO asserts update access and updates only isLockedByOwner; no modified timestamp change. Reload same provider, then AnnotationService.publicWrites under global nested DAO context.

Success 200 is full public annotation JSON plus `messages:[{"success":"The locking state of the annotation was successfully updated."}]`. Saved `full_json` can supply the database-backed fields for valid resolved Explorational rows: owner/user/contributors, stores, layer stats, timestamps in milliseconds, requester view config with owner fallback, teams, settings, tags plus dataset name, and restrictions reflecting changed lock. It is not the remote-version /info response. Public serialization needs real live dataset/organization/user/datastore/tracing-store dependencies.

Owner error defaults 400: `Only the owner of this annotation has permission to change the locked state of an annotation.` Type error defaults 400: `Only explorational annotations can be locked.` Update error defaults 400: `Could not change the isLockedByOwner state of the annotation.` Initial provider failure defaults 400; reload is explicitly 404. Serialization failure defaults 400: `Could not convert annotation to json.`

## GET /annotations/:typ/:id/sharedTeams

Source: `AnnotationController.scala:452`; `Team.scala:38,110,167`.

Secured action; resolve provider, require actual owner (403, `You are not authorized to view or edit this resource.`). No Private/state/lock/collaboration gate. Initial provider failure defaults 400. Return 200 bare array of readable live shared teams, each `{id,name,organization,isOrganizationTeam}`. No messages, compact-list `organizationId`, or created fields.

Unlike `full_json` (which intentionally serializes all teams under GlobalAccessContext), this controller's TeamDAO call applies requester read access: requester is a member of team OR an administrator of team's organization. An owner who ceased team membership can receive a subset of persisted sharing rows. TeamService.publicWrites additionally requires its organization through GlobalAccessContext. Rust organization-scoping policy requires live same-requester-organization teams/membership grants; foreign stored stale role rows must not broaden access.

## PATCH /annotations/:typ/:id/sharedTeams

Source: `AnnotationController.scala:461`; `Team.scala:110`; `Annotation.scala:863`.

Secured action, body is bare JSON array of strings (not `{teams:...}`). Resolve provider, require owner AND visibility != Private (403, same generic notAllowed message); no state/owner-lock/collaboration/mutex gate. Parse every team ID using ObjectId.fromString: exactly 24 hex characters, uppercase normalized to lowercase, no human-readable prefixes in body. Path ID uses normal ObjectId path binder (prefixes allowed). Invalid team ID defaults 400 with `The supplied resource id “<literal>” is not a valid ObjectId.` Validate every team with normal live TeamDAO findOne before any mutation; membership or team-organization admin suffices, team-manager flag is not required. Inaccessible/missing team defaults 400, `Could not access a team during annotation shared team update.`

DAO independently asserts annotation update access, then SERIALIZABLE transaction deletes all current annotation_sharedTeams rows and inserts every requested pair. Empty array clears. Duplicate IDs are not deduplicated; PK failure rolls transaction back (do not silently accept duplicates). FK requires real persisted annotation/team rows. Return 200 bare array of validated lowercase IDs in input order, no messages. No modified timestamp/activity/cache/remote changes beyond provider behavior. Lock live annotation and referenced live teams through the transaction to avoid soft-delete/visibility/owner races; no placeholder teams.

No builds run in this read-only task.
