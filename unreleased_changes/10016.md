### Added
- Added an MCP (Model Context Protocol) server at `/api/mcp`, so that AI agents such as Claude Code or Claude Desktop can work with a WEBKNOSSOS instance. It offers tools to create a short-lived API token for the WEBKNOSSOS Python library, to look up the documentation of that library, and to look up the [EM-Skills](https://github.com/yanchaoz/EM-Skills) collection of volume EM processing skills. It is disabled by default, enable it with `features.mcpEnabled = true`.
- MCP clients connect via OAuth: WEBKNOSSOS acts as an OAuth 2.1 authorization server (authorization code flow with PKCE, refresh token rotation, clients identified by client ID metadata documents or registered via Dynamic Client Registration). When connecting, the user chooses one of three permission levels (read, create/modify, delete). Connected applications are listed in the account settings, where they can be disconnected. Logging out everywhere disconnects all of them.
- Added short-lived API tokens for agents. They act for the user, limited to the permission level of the connection they were obtained through, expire after one day (configurable via `silhouette.tokenAuthenticator.shortLivedExpiry`), and are revoked together with the connection.
- Permissions of agent tokens are enforced centrally for all API routes and for datastore/tracingstore access. Set `webKnossos.tokenScopes.enforced = false` to only log what would be denied.

### Changed
- The WEBKNOSSOS API now also accepts an API token in the `Authorization: Bearer` header, in addition to the `X-Auth-Token` header.
